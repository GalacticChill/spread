# Spread — project guide

"Spread" is a mobile-first puzzle app about how things spread through graphs. It is a
PWA hosted on GitHub Pages at `https://galacticchill.github.io/spread/` (GitHub user
**GalacticChill**, repo **spread**). It will eventually contain **six game modes**, each
based on a real graph theory problem. All six are built: Spread, Containment, Threshold,
Rival, Origin and Wiring.

Follow this spec in every session. If a request conflicts with it, point that out
before changing course.

## Tech

- **Vite + TypeScript, no UI framework.** Rendering in **SVG** (built with DOM APIs).
- **vite-plugin-pwa** generates the manifest and service worker. The app must work
  **fully offline** (all assets and level data precached; no runtime network calls).
- Vite `base` is `/spread/` (the repo name) for GitHub Pages. Never use absolute
  paths like `/foo.png` in code; use `import.meta.env.BASE_URL` or relative imports.
- GitHub Actions workflow (`.github/workflows/deploy.yml`) runs tests, builds, and deploys
  to GitHub Pages on push to `main`. Pages source must be set to "GitHub Actions".
- **Game logic is pure and separate from rendering.** `src/core/` holds pure functions
  over a graph and a state (no DOM, no `window`, no `localStorage`). `src/ui/` renders
  and handles input. Core code is unit tested with **Vitest** (`npm test`).
- Before finishing any change: `npm test` and `npm run build` must both pass.

## Layout of the code

- `src/core/graph.ts` — graph types, adjacency, BFS distances.
- `src/core/spread.ts` — Mode 1 rules: `tap`, `tick`, `isComplete`, stars.
- `src/core/solver.ts` — par/optimal solver for Mode 1.
- `src/core/containment.ts` — Mode 2 rules: `toggleProtect`, `tick`, `canSpread`, stars.
- `src/core/containmentSolver.ts` — optimal (max saved) solver for Mode 2.
- `src/core/threshold.ts` — Mode 3 tick (`thresholdTick`, `thresholdOf`); taps and
  state are shared with `spread.ts`.
- `src/core/thresholdSolver.ts` — par solver for Mode 3.
- `src/core/rival.ts` / `rivalSolver.ts` — Mode 4 rules and optimal solver.
- `src/core/origin.ts` — Mode 5 rules, observation, verification, `allExplanations`.
- `src/core/wiring.ts` / `wiringSolver.ts` — Mode 6 rules and min-new-edges solver.
- `src/core/sandbox.ts` — Sandbox document (graph + mode + marks + settings), editing
  ops, generator specs, import/export parsing, `docToLevel`, and `solveDoc` (the single
  entry point used by the worker and tests).
- `src/core/stats.ts` — node/edge counts, degree sequence, components, diameter.
- `src/workers/solver.worker.ts` — runs `solveDoc` off the main thread (Vite
  `worker.format: 'es'`; the worker chunk is precached for offline use).
- `src/core/families.ts` — generators for graph families with layouts (paths, cycles,
  stars, wheels, grids, trees incl. `layeredTree(parent[])`, clusters joined by bridges,
  Q3, Petersen), `withThresholds` and `normalize`.
- `src/core/level.ts` — level JSON types (a union per mode) and validation.
- `src/levels/<mode>.json` — levels, generated by `npm run levels` (runs
  `scripts/gen-levels.ts`; targets are precomputed by the solvers). Edit the script,
  not the JSON, then regenerate. `tests/levels.test.ts` re-solves every level, so stale
  JSON fails the tests.
- `src/ui/shell.ts` — the shared game screen (stats, board, undo/tick/restart,
  keyboard, saving, results card). A mode plugs in via the `GameRules<S>` interface;
  `src/ui/game.ts` holds each mode's adapter. Optional hooks: custom button label,
  hint line, marker rings, added edges + drag/tap handlers, `tickIsFinal`, and a
  0-star result for a failed level (not saved).
- `src/ui/modes.ts` — mode registry (title, tagline, rules card text, levels).
- `src/ui/sandbox.ts`, `src/ui/editor.ts`, `src/ui/solverClient.ts` — Sandbox screen,
  its editing canvas, and the cancellable worker client.
- `src/ui/` also has the home/level-select screens, the SVG board (node colors:
  `none | orange | blue | gray | white`, optional number labels inside nodes, dynamic
  marker rings, player-added edges with drag-to-connect and tap-to-remove), storage, haptics, and the router (hash-based, so it
  works on Pages and offline).

## Visual design

- **Purely abstract**: nodes are circles, edges are lines. No people, plants, fires,
  or illustrations, ever.
- Dark, calm background (near-black slate). Uncolored nodes are a muted outline.
  **Orange `#FF8A1F`** is the active state. Later modes add **blue**, **gray**
  (immune/blocked) and **white** (selected). Colors live as CSS custom properties in
  `src/style.css`.
- Minimal text, clean system sans-serif. Portrait phone layout first; must also look
  good on desktop.
- Tap targets at least **44px** (node hit-testing uses a nearest-node radius, not the
  drawn circle; added edges are hit within 16px). A dashed white ring marks nodes that
  are "wrong" (Origin's bad guess, Wiring's unreached nodes); a faint solid ring marks
  where something started (fire sources, blue starts, Wiring's seed). Short, smooth animations when nodes change color; on each tick the
  spread visibly **ripples outward along edges**. Light haptics via `navigator.vibrate`
  where supported. Respect `prefers-reduced-motion`.
- Screens: **home** (mode list), **level select** (grid with star ratings), **game**,
  and a short **rules card** shown the first time each mode is opened (re-openable
  with "?").

## Data model

- Graph: nodes with `id` and `x, y` normalized to 0–1 (scaled to the screen),
  undirected edges as `[a, b]` index pairs. Nodes may carry optional per-node
  attributes for later modes (e.g. `threshold`).
- Levels are JSON: `id`, `mode`, `name` (graph-family name shown subtly in game, e.g.
  "Petersen graph"), `graph`, mode-specific `params`, and a precomputed target
  (`par` for Spread and Threshold, `optimum` for Containment, Rival and Wiring;
  `explanations` for Origin). Threshold levels store r
  on each node as `node.threshold` (required, ≥ 1).
- Progress (best score and stars per level; lower is better for Spread/Threshold
  moves, Origin guesses and Wiring links; higher for Containment and Rival) and "rules seen" flags are saved in
  `localStorage` (versioned keys, wrapped in try/catch so the app still works without it).

## Mode 1: Spread

- Tapping an uncolored node turns it orange (**1 move**). **Tick** advances one step:
  every node adjacent to an orange node turns orange (**1 move**). Taps and ticks can be
  interleaved freely. Goal: make every node orange in as few total moves as possible.
- Undo and Restart buttons. Show the move counter and the par.
- **Par solver**: orange only grows, so tapping early is never worse. Optimum =
  min over t of (t + minimum number of seeds such that every node is within distance t
  of a seed), i.e. t + the distance-t domination number. Computed with BFS distances plus
  exact search (bitmask branch-and-bound) for minimum distance-t dominating sets; fine for
  graphs up to ~30 nodes. Unit tests on path, star, cycle, complete graph with
  hand-verified answers.
- Stars: **3** for matching par, **2** for par+1, **1** for completing.
- On completion show score, par, stars, with **Next Level** and **Retry**.

## Mode 2: Containment (firefighter problem, Hartnell 1995)

- Orange starts on one or more given **source** nodes (drawn with a faint ring).
- Each turn the player may protect **up to k** uncolored nodes (k per level, usually 1;
  shown as "Shields"). Protections placed this turn show **white** (selected) and can be
  tapped again to take them back; on Tick they become permanent **gray** and can never
  turn orange. Then **Tick**: orange spreads to every unprotected uncolored neighbor.
- The game ends as soon as orange can no longer spread (this can happen right after a
  protection, without a tick). Score = **nodes saved** (not orange). Undo and Restart.
- **Solver**: exhaustive search with memoization. Protecting never hurts, so each turn
  protects exactly min(k, threatened). State = (front, threatened): only nodes that just
  turned orange can spread, and free nodes orange can't reach are safe forever. Memo
  key on those two bitmasks; ≤ 30 nodes. Keep levels small enough that solving takes
  well under a second (largest today: 5×5 grid with k = 2, ~0.2 s). Unit tests on paths,
  stars, trees with hand-verified answers, plus brute force over the real game rules.
- Stars: **3** for saving the optimum, **2** for optimum−1, **1** for finishing.

## Mode 3: Threshold (bootstrap percolation / target set selection)

- Same as Spread (taps and ticks, each one move, freely interleaved), except each node
  shows a small threshold number **r** inside its circle. On a tick an uncolored node
  turns orange only if **at least r of its neighbors** are orange (counted before the
  tick). Spread is the case r = 1 everywhere. A tick that changes nothing still costs a
  move. Goal: everything orange in as few moves as possible. Stars as in Spread.
- **Solver**: activation is monotone, so seeding first is optimal again: optimum =
  min over seed sets S of |S| + ticks for S to fill the graph. For each tick budget t,
  find the fewest seeds that fill within t ticks by DFS over "seed / don't seed" in a
  fixed node order, pruned by the monotone bound "even seeding every undecided node
  fails within t ticks". Nodes with r > degree are forced seeds. ≤ 30 nodes; the 5×5
  grid takes ~40 ms. Tests: hand-verified pars (paths, cycles, complete graphs, wheel),
  agreement with the Spread solver when r = 1, and brute force over the game rules.

## Mode 4: Rival (competitive diffusion vs. a deterministic opponent)

- **Blue** starts on given nodes (ringed) and spreads on every tick. The player has a
  total **budget of orange taps**, usable on uncolored nodes any time between ticks.
  On a tick both colors spread at once: reached by orange only → orange, blue only →
  blue, both on the same tick → **gray** (contested, blocked). Colored nodes never
  change. The game ends when nothing can change (no spread possible and no useful taps).
  Score = orange nodes. Stars: optimum / optimum−1 / finished.
- **Solver**: tapping earlier is never worse (earlier orange reaches everything at
  least as early and only slows blue), so the optimum is an exhaustive search over seed
  sets of size min(budget, free) placed before the first tick. A brute-force test over
  every interleaving of taps and ticks backs this up.

## Mode 5: Origin (source identification)

- The player sees the result of a Spread run (r = 1) from **s hidden sources** after
  **T ticks**, picks s orange nodes as suspects (white) and presses **Check**. **Any**
  seed set that reproduces the observation exactly is accepted (verified by simulation).
  **3 guesses**; a wrong guess rings the nodes it would color incorrectly (missed or
  extra). Undo/Restart can't refund guesses (`tickIsFinal`). Out of guesses = failed
  (0 stars, original sources revealed). Stars: 1st guess 3, 2nd 2, 3rd 1.
- **Timed levels**: showing true infection times would give the answer away (sources =
  the 0s), so the first `hidden` ticks are unobserved and each orange node shows when it
  turned orange counting from tick `hidden` (0 = already orange then).
- `allExplanations` counts valid answers for level design (all current levels: 1).

## Mode 6: Wiring (network design)

- Nodes, possibly fixed edges, one **seed** (ringed), tick limit **T**, and a new-link
  **budget**. Drag node → node to add a link; tap an added link to remove it. **Tick**
  runs a test spread from the seed (editing resets it); after T ticks without reaching
  everyone, unreached nodes are ringed. Goal: everyone within T ticks with as few new
  links as possible. Stars vs. the minimum: par / par+1 / done.
- **Solver**: iterative deepening on the number of new edges. Branch on the farthest
  unreached node v: the last new edge (x, y) on v's shortest path has y within T−1 hops
  of v in the current network, so try y in that ball and any x. Edge sets already
  tried are skipped. Brute-force tested against trying all edge subsets.

## Sandbox (#/sandbox, card on the home screen)

- Tools: **Draw** (tap empty space = add node; drag node→node = link; drag node→empty =
  new linked node), **Move**, **Erase** (tap node or link), and a mode-specific **Mark**
  tool (Fire / Blue / Source / Seed; in Threshold it cycles r = 1–4 on a node). Undo
  (also Ctrl/Cmd+Z). Max 60 nodes. The editor canvas maps 0–1 onto a fixed square (no
  auto-fit, so nodes don't jump while editing).
- **Generate**: path, cycle, star, complete, complete bipartite, grid, hypercube Q1–Q5,
  binary tree, Petersen, Erdős–Rényi G(n, p).
- **Stats** line: nodes, edges, connected/components, diameter, degree sequence.
- Mode picker + settings (Shields, Taps, Ticks, Timed, Links). **Solve** runs `solveDoc`
  in the Web Worker with a spinner and **Cancel** (terminates the worker); results are
  shown as a summary plus dashed rings on nodes / dashed links (Containment rings are
  numbered by turn). Graphs over a solver's limit get a "too large to solve exactly"
  note. **Play** solves first (cancellable) to get par/goal, then opens the shared game
  shell at #/sandbox/play; if unsolvable, it plays with "?" as the target (1 star for
  finishing). Sandbox plays never save progress; results offer Retry / Edit graph.
- **File** menu (⋯): save under a name / open / delete (localStorage), Export (JSON +
  Copy, falls back to selecting the text), Import (paste a sandbox doc, a level from
  the game files, or a bare `{nodes, edges}` graph; positions outside 0–1 are rescaled),
  New. The current graph autosaves on every edit.

## Levels

- Mode 1: ~15 levels that teach intuitions progressively using classic families:
  paths, stars, cycles, complete graphs, trees, grids, two dense clusters joined by a
  bridge, the hypercube Q3, and the Petersen graph.
- Mode 2: 12 levels: paths, hub-and-spoke (star, spider), trees (incl. one where
  "protect the biggest subtree" is wrong, and one with two fires), clusters with
  bottleneck bridges, and grids (5×5 with k = 2).
- Mode 3: 13 levels: paths (r = 1, then r = 2), C6, K5, grids with all r = 2 (classic
  2-neighbor bootstrap percolation: 3×3, 4×4, 5×5), a binary tree, two clusters with a
  bridge, Q3, Petersen, and two hub levels (Wheel W6, Hub and ring) where seeding the
  high-degree hub is strictly worse than par although it's the best seed in Spread
  (a test locks this in).
- Mode 4: 10 levels: paths, hub and spoke, wheel, C10 with two blue fronts, binary tree,
  two clusters + bridge, 4×4 grid with blue in two corners, Petersen, 5×5 with two blues.
- Mode 5: 10 levels: P7, C10, 5×5 plus, Petersen, binary tree, two sources on P11 and
  on the 5×5 grid (separate and overlapping diamonds), and two timed levels.
- Mode 6: 9 levels: path shortcut, five loose nodes (T = 1 star), two clusters with no
  bridge, C8, P9, three loose paths, C12 (needs 3), binary tree from a leaf, 4×4 grid.
- Layouts make the structure recognizable. At 375px width, neighboring nodes should
  stay ≥ 44px apart (e.g. at most ~8 leaves side by side in a tree).
