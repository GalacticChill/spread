# Spread — project guide

"Spread" is a mobile-first puzzle app about how things spread through graphs. It is a
PWA hosted on GitHub Pages at `https://galacticchill.github.io/spread/` (GitHub user
**GalacticChill**, repo **spread**). It will eventually contain **six game modes**, each
based on a real graph theory problem. Mode 1 (Spread) is built; the others are future work.

Follow this spec in every session. If a request conflicts with it, point that out
before changing course.

## Tech

- **Vite + TypeScript, no UI framework.** Rendering in **SVG** (built with DOM APIs).
- **vite-plugin-pwa** generates the manifest and service worker. The app must work
  **fully offline** (all assets and level data precached; no runtime network calls).
- Vite `base` is `/spread/` (the repo name) for GitHub Pages. Never use absolute
  paths like `/foo.png` in code; use `import.meta.env.BASE_URL` or relative imports.
- GitHub Actions workflow (`.github/workflows/deploy.yml`) runs tests, builds, and deploys
  to GitHub Pages on push to `main`. Pages source must be set to "GitHub Actions".
- **Game logic is pure and separate from rendering.** `src/core/` holds pure functions
  over a graph and a state (no DOM, no `window`, no `localStorage`). `src/ui/` renders
  and handles input. Core code is unit tested with **Vitest** (`npm test`).
- Before finishing any change: `npm test` and `npm run build` must both pass.

## Layout of the code

- `src/core/graph.ts` — graph types, adjacency, BFS distances.
- `src/core/spread.ts` — Mode 1 rules: `tap`, `tick`, `isComplete`, stars.
- `src/core/solver.ts` — par/optimal solver for Mode 1.
- `src/core/families.ts` — generators for classic graph families with layouts.
- `src/core/level.ts` — level JSON types and validation.
- `src/levels/spread.json` — Mode 1 levels (generated by `npm run levels`, which
  runs `scripts/gen-levels.ts`; par is precomputed by the solver). Edit the script,
  not the JSON, then regenerate.
- `src/ui/` — screens (home, level select, game, rules card), SVG board, storage,
  haptics, router (hash-based, so it works on Pages and offline).

## Visual design

- **Purely abstract**: nodes are circles, edges are lines. No people, plants, fires,
  or illustrations, ever.
- Dark, calm background (near-black slate). Uncolored nodes are a muted outline.
  **Orange `#FF8A1F`** is the active state. Later modes add **blue**, **gray**
  (immune/blocked) and **white** (selected). Colors live as CSS custom properties in
  `src/style.css`.
- Minimal text, clean system sans-serif. Portrait phone layout first; must also look
  good on desktop.
- Tap targets at least **44px** (node hit-testing uses a nearest-node radius, not the
  drawn circle). Short, smooth animations when nodes change color; on each tick the
  spread visibly **ripples outward along edges**. Light haptics via `navigator.vibrate`
  where supported. Respect `prefers-reduced-motion`.
- Screens: **home** (mode list), **level select** (grid with star ratings), **game**,
  and a short **rules card** shown the first time each mode is opened (re-openable
  with "?").

## Data model

- Graph: nodes with `id` and `x, y` normalized to 0–1 (scaled to the screen),
  undirected edges as `[a, b]` index pairs. Nodes may carry optional per-node
  attributes for later modes (e.g. `threshold`).
- Levels are JSON: `id`, `mode`, `name` (graph-family name shown subtly in game, e.g.
  "Petersen graph"), `graph`, mode-specific `params`, and precomputed `par` where useful.
- Progress (best score and stars per level) and "rules seen" flags are saved in
  `localStorage` (versioned keys, wrapped in try/catch so the app still works without it).

## Mode 1: Spread

- Tapping an uncolored node turns it orange (**1 move**). **Tick** advances one step:
  every node adjacent to an orange node turns orange (**1 move**). Taps and ticks can be
  interleaved freely. Goal: make every node orange in as few total moves as possible.
- Undo and Restart buttons. Show the move counter and the par.
- **Par solver**: orange only grows, so tapping early is never worse. Optimum =
  min over t of (t + minimum number of seeds such that every node is within distance t
  of a seed), i.e. t + the distance-t domination number. Computed with BFS distances plus
  exact search (bitmask branch-and-bound) for minimum distance-t dominating sets; fine for
  graphs up to ~30 nodes. Unit tests on path, star, cycle, complete graph with
  hand-verified answers.
- Stars: **3** for matching par, **2** for par+1, **1** for completing.
- On completion show score, par, stars, with **Next Level** and **Retry**.

## Levels (Mode 1)

~15 levels that teach intuitions progressively using classic families: paths, stars,
cycles, complete graphs, trees, grids, two dense clusters joined by a bridge, the
hypercube Q3, and the Petersen graph. Layouts make the structure recognizable.
